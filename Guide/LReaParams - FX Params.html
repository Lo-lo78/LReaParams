This is the replacement for the old Speak FX Params - TrackTake Navigator Lua guide (0.346). It describes the native reaper_lreaparams.dll, using the Lua guide as the functional starting point and the current C++ source as the authority for changed behavior. The companion Track Params guide documents track controls and routing. No Stretch Marker script is part of LReaParams.

1. Installation, actions and accessibility

Put reaper_lreaparams.dll in REAPER's UserPlugins folder inside its resource path, restart REAPER, and locate LReaParams: FX Params and LReaParams: Track Params in the Action List. Assign the preferred global shortcuts there. The DLL does not require Open FX Params.lua, Open Track Params.lua, or the two original Lua navigators as launcher actions. Those Lua files are historical references, not commands to run alongside the DLL.

OSARA is required for spoken messages and shortcut-help coordination; NVDA reads the native keyboard window, its title/review, and standard Windows text-edit controls. NVDA+Up reviews the selected control; Tab requests fuller context. Keyboard capture applies only while the LReaParams navigator owns focus. If OSARA shortcut help is enabled, navigator keys are not executed as ordinary edits. Do not treat this window like a global keyboard hook.

To switch to the other workspace, use Ctrl+Tab. Esc backs out of the current editor or page and eventually exits the navigator. Ctrl+Q returns focus to REAPER while allowing the supported MIDI live-control session to stay active; it is not the same as Esc. Use the REAPER action LReaParams: Stop background MIDI to stop background MIDI explicitly.

2. Main navigation and grids

FX Params navigates track FX, take FX, Master FX, and monitoring FX within their valid contexts. Each parameter is a cell in a grid. Normal arrow keys navigate; the exact horizontal spacing depends on the grid width. F1/F2 decrease/increase the grid column count. F3 reviews grid/step information. Home/End and Ctrl+Home/End navigate to local or overall boundaries as appropriate; navigation stops silently at an edge. Tab speaks the full current context; the backslash key gives a concise context announcement. Letters, digits and printable punctuation cycle through matching visible parameter names; Shift plus a printable character searches backward. The actual Windows keyboard layout is used.

Enter switches between Grid and Value for an editable parameter. In Value mode, Up/Down adjust rather than navigate; Esc returns to Grid. Alt+Up/Down adjusts the current value directly from Grid. Alt+Page Up/Down uses a coarser increment; Alt+Home/End moves to the parameter's limits. Alt+Left/Right changes that parameter's step scale from -10 to +10; Ctrl+Backspace restores Grid 10 and Step 0. Per-parameter steps are retained by the profile. Ctrl+E opens a real accessible numeric EDIT field, Enter commits and Esc cancels. If the host can only provide normalized/raw units, the edit identifies them: do not assume that a typed number is dB or Hz.

Backspace restores a parameter's default; Ctrl+Shift+Backspace invokes the broader saved Default restoration workflow (with structured ReaEQ handling where supported). Ctrl+T affects speech generated by MIDI CC for the current parameter; ordinary grid announcements and NVDA review are separate.

3. Internal FX browser — F10

F10 opens the internal FX browser from the parameter grid; in the browser, F10 (or Enter on the selected FX) loads the highlighted FX into its parameter grid. Ctrl+P no longer opens the browser: it was removed in version 0.0.61. The browser tracks FX in the current scope, with separate Master and Monitor columns when navigating that context; Left/Right switch between those two chains. The browser offers vertical selection, page jumps, first/last selection, first-character search, Tab review, bypass/offline/Delta Solo, and moving an FX without confusing movement with selection.

Ctrl+Up/Down changes the selected FX, Ctrl+Page Up/Down physically reorders it, and Ctrl+Shift+Up/Down moves to another track with FX while staying in the browser. Ctrl+B, Ctrl+Alt+B, Ctrl+D, and Ctrl+Shift+D preserve their FX actions. From the browser F11 selects the focused FX and enters its audio pin matrix, if it has usable pins. Ctrl+Shift+F and Alt+Shift+F open the native REAPER windows rather than the internal browser.

4. Audio Pin Connector — F11 (moved from Track Params)

This page is inside FX Params, not Track Params. Open F11 from Grid, Value, F7, or the internal browser, on an FX with audio pins. It works for supported Track FX, Take FX and Monitor FX. Each column is an input or output audio pin; each row is an existing track audio channel. The display covers channels 1–128 where the context and host provide them, using REAPER's two pin-mapping banks. It does not increase the track's channel count and does not manage MIDI pins.

An occupied cell begins with the concise announcement “Attive. Input 1 left. Receives from track channel 1” (similarly for Output). An empty cell has no “Disconnected” prefix: for example “Input 2 right. Receives from track channel 1”. The change is written through REAPER pin-mapping APIs with undo and readback checks. The GUID/context check avoids editing the wrong FX after a chain change. Do not use the old Track F5 or Ctrl+S pin workflow.

5. Parameter views, Custom order, F7 and Groups

Plugin order follows the FX's actual parameters and is the protected baseline. Custom order is a separately saved view that can rearrange, hide, duplicate or rename displayed occurrences without changing the plugin's real parameter numbers. Groups are independent ordered sets; changing a Group does not reorder Custom, and changing Custom does not rewrite a Group. A loaded Group can remember its last navigation position. The stored data are tied to each FX profile, not to arbitrary names in a global Parameter Library.

F7 is the deliberate structural-edit workspace: it handles selections (including snake/range selection), group or custom rearrangement, Copy/Cut/Paste of parameter occurrences, hiding/unhiding where permitted, and rename actions. Plugin order remains a reference rather than an editable reordering target. Use the available Custom/Group edit path for structural changes and leave F7 to return to ordinary parameter-value operation. Shift+arrow selects cells in F7 (the first shift movement anchors the current cell); Ctrl+Shift+Home/End extends selection to global edges; Alt+Shift+arrows travels between selected cells by grid geometry without altering selection. F7 selection and the normal parameter grid are deliberately different.

Cut is local to the edit container; Copy can transfer a selection into another eligible edit context. In a loaded Group, the separate All parameters view is a copy source rather than permission to destroy unrelated parameters. Renaming is intentional in F7. F7 search is a lens: filtering does not require destroying selection. Positions remembered for Group slots are independent from Custom order.

FX Memories is not F8

Press Ctrl+Shift+M or invoke the dedicated LReaParams: FX Memories REAPER action. Its columns manage saved parameter positions, Groups, copied/hidden entries, learned MIDI mappings, Default snapshots and the available profile categories. Left/Right chooses a column, Up/Down chooses an entry, Tab reviews, Enter opens/applies where supported, Delete removes or requests confirmation for destructive operations. A saved Default can restore FX values without erasing unrelated memories. Its protected Delete/reset procedure explicitly confirms before changing the stored memory configuration. Esc returns to navigation. The Lua-era instruction “F7 then F8 for the memory manager” is obsolete.

6. Compare A/B — F8

F8 once toggles Original and Compare/Edited snapshots for the current FX. Original is initially captured from the real sound when the FX is first entered; opening the navigator does not apply a snapshot or change the sound. Changes made on Compare can be recalled after listening to Original. Press F8 twice quickly to update the Original reference from the currently audible sound without toggling sides. The short delay before a single F8 action is intentional so Windows' double-press interval can be recognized. A/B snapshots are session/FX-instance state, not new plugin parameters; they survive reopening the navigator within the same REAPER session but not a new REAPER session. The former in-grid Compare virtual parameter is removed.

Fixed assignments are stored with the FX profile and use pickup/soft takeover; duplicate CC bindings can be reassigned. Floating CC is temporary and follows whichever supported parameter is selected, temporarily taking priority over fixed mappings. MIDI speech defaults to off per parameter; Ctrl+T does not mute normal navigation. Ctrl+Q may leave eligible MIDI processing running with REAPER focus. Automation indications such as Auto come from actual REAPER envelopes, not a purely visual flag. Destructive automation clearing is confirmed before execution; do not confuse it with the per-parameter Ctrl+Shift+A toggle.

8. ReaEQ, ReaComp, ReaGate and FX commands

For recognized Cockos effects the DLL offers the migrated virtual handling documented by the original Lua: ReaEQ per-band frequency/gain/bandwidth/type navigation, and special ReaComp / ReaGate controls with host readback. Real plugin values and REAPER envelopes remain the source of truth; the guide does not imply that every third-party FX exposes such virtual controls. Presets use Alt+F1/F2, bypass Ctrl+B, Delta Solo Ctrl+D, offline Ctrl+Alt+B, and FX movement Ctrl+Page Up/Down. Preserve the FX chain context when moving between track, take, Master and Monitor chains.

9. Search, clipboard and Default

Ctrl+F starts an accessible search by displayed parameter label, with Enter to accept and Esc to cancel. Ctrl+R opens saved recent searches, and Ctrl+Shift+R reads the broader FX context. The search filter affects current visible results, not the real FX parameter numbers. Outside structural editing, Ctrl+C copies a value, Ctrl+V pastes compatible value/snapshot data, and Ctrl+Alt+Shift+C copies a whole-FX snapshot. Within F7 these same clipboard keys are structural instead. Standard Windows Ctrl+A/C/X/V remains available in text EDIT fields. The Default snapshot management in FX Memories is separate from restoring a single parameter with Backspace.

11. Saved data and old Lua migration

The DLL uses its own data tree at REAPER resource path/LReaParams/; FX profiles live in Plugins (typically .fx files), track/project data in Tracks (.tp), along with its other Settings/Backups locations. It can import relevant historical Lua TXT layouts on first run/import without requiring the Lua scripts to execute. REAPER itself remains responsible for storing plugin state, real envelopes, routing and take/track FX chains in the project.

Some historical Lua behaviors do not carry over literally: Parameter Library is excluded; F8 is A/B Compare rather than an F8 memory manager; Ctrl+P is not the browser; the pin connector is F11 here, not Track F5. Do not run Lua and native navigators simultaneously. This guide is aligned to the 0.0.61 TEST61.4 source, not proof that a particular downloaded DLL has completed GitHub Actions build and NVDA/REAPER runtime verification.
