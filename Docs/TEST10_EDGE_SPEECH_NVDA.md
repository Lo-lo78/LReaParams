# LReaParams TEST10 (0.0.11) — navigation bounds, absolute values, NVDA

This package contains **C++ source only**. Build with GitHub Actions; no local build has been performed.

## Changes

1. In both FX Params and Track Params, **Alt+Home = maximum** and **Alt+End = minimum**. The same direction applies to plain Home/End when in FX Value mode. Plain Home/End in Grid mode continue to move to the first/last cell and are not reversed.
2. A move that reaches an edge without changing the current item makes no LReaParams OSARA announcement. This covers FX columns, Track F1 rows, Track F2/F3 fields, and repeated F1/F2/F3 page selections.
3. After processing a key, the native review EDIT and title receive Win32 updates **only if** their actual contents have changed. Focus recovery likewise occurs only when the displayed context/value changes. No-op navigation keys no longer trigger redundant focus recovery.
4. The native read-only EDIT is populated with the initial review text **before focus is assigned**, so NVDA does not see an empty EDIT immediately followed by a text update.
5. The actual NVDA+T title for FX Params now begins `LReaParams - FX Params -` and includes the plugin name, track/take and Grid/Value mode, consistent with the explicit OSARA contextual announcement.
6. FX NVDA+Up still reads only `parameter, value`; Track NVDA+Up retains `track, parameter, value` (including send/receive context).

## Limitations

NVDA may still automatically announce the native read-only EDIT and its role when it receives Windows focus. The source changes reduce avoidable duplicate events, but eliminating *all* NVDA focus speech would require a different accessible focus object or an NVDA-specific integration, which is not part of TEST10. Do not remove the EDIT: it currently enables NVDA+Up.

## REAPER checks

- Open FX Params, check that the first explicit OSARA message contains FX name, track and current parameter. Check NVDA+T and NVDA+Up separately.
- On any FX grid column's top/bottom, press Up/Down repeatedly; at the first/last column, press Left/Right. No redundant LReaParams message should occur.
- In Track F1, test the first/last tracks and the first/last parameter of a track. In F2/F3, test first/last send/receive and top/bottom of each 14-field column.
- Check Alt+Home (maximum) and Alt+End (minimum) on a safely editable track parameter and a safely editable FX parameter. Verify that repeating either at its limit is silent and that Undo still works.
- Check that NVDA+Up reads only the desired context and parameter information. Confirm that tab remains unassigned and Escape restores REAPER focus.

These are source-level changes, **not** runtime-verified fixes. If NVDA still speaks a boundary despite the navigator not emitting an announcement, the remaining event is likely generated by NVDA itself from the focused EDIT and should be diagnosed from a reproduction recording or NVDA log.
